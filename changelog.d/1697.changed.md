WebSocket Origin matching no longer applies `*` or leading-dot `ALLOWED_HOSTS` entries. If your `ALLOWED_HOSTS` uses one, list your public origin (for example `https://boards.example.com`) in `CORS_ALLOWED_ORIGINS` or `CSRF_TRUSTED_ORIGINS`, otherwise browser WebSocket connections are refused. Exact `ALLOWED_HOSTS` entries keep matching with scheme and port ignored. System check `accounts.W002` (`manage.py check` / `check --deploy`) now warns about exactly this configuration: `DEBUG` is off, `ALLOWED_HOSTS` has a `*` or leading-dot entry, and there is neither an exact public host in `ALLOWED_HOSTS` nor a non-loopback origin in `CORS_ALLOWED_ORIGINS` / `CSRF_TRUSTED_ORIGINS`. Listing your public origin clears it, or silence it with `SILENCED_SYSTEM_CHECKS = ["accounts.W002"]` if the setup is intended. This supersedes the 1.2.0-beta.2 description of `accounts.W002`.
