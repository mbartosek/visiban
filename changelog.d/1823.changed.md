Card list `GET /boards/{id}/cards/` and MCP `list_cards` now both treat a negative or non-integer `offset` as 0 (as on every other endpoint) instead of returning an error. A bad card-list `limit` now returns `{detail, code: "invalid_query_param"}` instead of the field-keyed `{"limit": [...]}` body. `limit` naming and the MCP `total`/`truncated` keys are unchanged and now documented as deliberate.
