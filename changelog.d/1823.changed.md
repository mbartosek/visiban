Card list `GET /boards/{id}/cards/` now treats a negative or non-integer `offset` as 0 (as on every other endpoint) instead of returning 400, and MCP `list_cards` now clamps a negative `offset` to 0 instead of returning a validation error (a non-numeric `offset` is still rejected by the MCP tool schema). A bad card-list `limit` now returns `{detail, code: "invalid_query_param"}` instead of the field-keyed `{"limit": "..."}` body. `limit` naming and the MCP `total`/`truncated` keys are unchanged and now documented as deliberate.
