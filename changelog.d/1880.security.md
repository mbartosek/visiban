Public board share links are now resolved by a stored SHA-256 hash of the share token, as invite links are, instead of by the token itself. Migrations `boards/0087`–`0089` add the hash, fill it in for existing share links (which keep working), and build its unique index concurrently. The share API responses are unchanged. During a rolling upgrade, a share link created by a not-yet-upgraded backend pod after migration `0088` has run must be regenerated (#1880).
