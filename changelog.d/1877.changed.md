With `EMAIL_VERIFICATION=mandatory`, `POST /api/v1/auth/registration/` (and the `/accounts/signup/` form) now gives a registration for an address that is already in use the same `201 {"detail": "Verification e-mail sent."}` response as any other registration, in line with the invite, member and login flows. No account is created or changed, and the address is emailed a notice with a password-reset link instead of a confirmation link. With `optional` or `none` (the default is `optional`), where a new registration is signed in straight away, the existing `400` response is unchanged.
