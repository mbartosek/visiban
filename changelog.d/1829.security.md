Group access now ignores a group membership whose stored role is not one of the four roles (admin, member, collaborator, viewer), as board access already did: such a row no longer lists the group, opens its member, label, subgroup and board routes, or admits the user to the group WebSocket channel, and an inherited row of that kind is left out of the group member list. Owning a group without a membership no longer lists it either; every group owner already holds an admin membership, which upgrading restores where it was missing (#1786). The group channel now sends `board.created` and `board.updated` only to subscribers who can open that board. Card comment and attachment writes check an explicit list of allowed roles instead of refusing only viewers, an import matches users only through the importer's own memberships with a recognized role, and the default board can only be one where the user's own membership has a recognized role. No API accepts such a role value, so installs that never edited membership rows directly see no change (#1829, #1726).
