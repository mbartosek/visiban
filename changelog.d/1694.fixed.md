The `suppressions-check` CI job, which is supposed to fail a pipeline when a temporary `SUPPRESSED-UNTIL(#N)` suppression cites an issue that has since closed, was sending a CI job token to a GitLab API endpoint that rejects it — so every lookup silently read as inconclusive and the gate could never actually block a closed-issue citation. It now resolves every cited issue in one batched, retried, unauthenticated-or-token-backed request that never sends a job token, and also blocks on a cited issue the tracker cannot find at all (deleted or confidential) instead of treating that the same as a network failure (#1694)
