The account rules that require an interactive session (setting a first password, changing the email address, changing the username, disconnecting a sign-in provider) and the WebSocket ticket binding now check positively that the request was authenticated by a session. An authenticator that returns no credential object is no longer treated as a session, so extension authenticators of that kind now receive `403 Forbidden` on these rules. Requests authenticated by a browser session are unchanged, and personal access tokens and the login API token are still refused.
